# Установка Evolet HRM на обычный хостинг (cPanel)

Пошаговая инструкция: первая установка, обновление, резервные копии и что делать, если что-то не работает.

Рассчитана на обычный «шаред»-хостинг с cPanel: без постоянно работающих процессов, с cron, с SSH или без него.

В примерах используются условные имена — подставьте свои:

| В инструкции | Что это | Где посмотреть |
| --- | --- | --- |
| `USER` | имя учётной записи cPanel | правый столбец на главной cPanel, «Current User» |
| `/home/USER` | домашняя папка на сервере | там же, «Home Directory» |
| `hrm.example.tj` | адрес, по которому будет открываться система | — |
| `PHP` | полный путь к PHP 8.4 для командной строки | см. раздел 1.2 |

---

## Короткий чек-лист перед началом

- [ ] На хостинге можно выбрать **PHP 8.4** (или новее) и включить нужные расширения (раздел 1).
- [ ] Есть **MySQL 5.7+ / 8** или **MariaDB 10.3+**.
- [ ] Есть **cron** (в cPanel — «Cron Jobs»). Узнайте у хостинга минимальный интервал: нужен запуск **каждую минуту**; если разрешено только раз в 5–15 минут — система будет работать, но письма будут уходить с такой задержкой.
- [ ] Для адреса системы выпущен **SSL-сертификат** (https). Без него войти в систему не получится.
- [ ] Создан **почтовый ящик** для писем системы, например `hrm@example.tj`, и известен его пароль.
- [ ] Известно, есть ли **SSH** или «Terminal» в cPanel. Без них установка тоже возможна (раздел 5.2), но чуть дольше.
- [ ] Все изменения в проекте **закоммичены** (`git status` чистый) — на сервер уходит то, что в коммите.
- [ ] Тесты проходят: `php artisan test`.

## 1. Требования к хостингу

### 1.1. PHP и расширения

**PHP 8.4.1 или новее** — и для сайта, и для командной строки (cron).

В cPanel: **MultiPHP Manager** → выбрать домен → PHP 8.4. Расширения включаются в **Select PHP Version** (или «PHP Extensions»).

Нужные расширения:

| Расширение | Зачем |
| --- | --- |
| `pdo_mysql` | база данных |
| `mbstring`, `ctype`, `tokenizer`, `filter`, `hash`, `session`, `pcre`, `json` | сам Laravel (обычно включены всегда) |
| `openssl` | шифрование, отправка почты по SSL |
| `dom`, `xml`, `libxml` | письма (вёрстка писем) |
| `fileinfo` | проверка загружаемых файлов |
| `gd` (с поддержкой JPEG, PNG и WebP) | фото сотрудников и оборудования |
| `exif` | правильный поворот фото с телефона |
| `iconv`, `zlib`, `curl` | вспомогательные библиотеки |

Настройки PHP (cPanel → **MultiPHP INI Editor**):

| Настройка | Значение | Зачем |
| --- | --- | --- |
| `upload_max_filesize` | `16M` | одно фото оборудования — до 12 МБ |
| `post_max_size` | `64M` | несколько фото за один раз |
| `memory_limit` | `256M` | обработка больших фото |
| `max_execution_time` | `60` | |

### 1.2. Какой PHP запускает cron

На хостинге часто стоит несколько версий PHP, и команда `php` в cron может оказаться старой. Нужен **полный путь** к PHP 8.4. Обычно это один из:

```
/opt/cpanel/ea-php84/root/usr/bin/php
/opt/alt/php84/usr/bin/php
/usr/local/bin/php
```

Проверка (в SSH или Terminal): `/opt/cpanel/ea-php84/root/usr/bin/php -v` — должно показать `PHP 8.4.x (cli)`. Если не уверены — спросите поддержку хостинга: «какой путь к PHP 8.4 CLI для cron?».

Дальше в инструкции этот путь обозначен словом `PHP`.

### 1.3. База данных

cPanel → **MySQL Databases**:

1. Создать базу, например `USER_hrm`.
2. Создать пользователя, например `USER_hrm`, с длинным паролем.
3. «Add User To Database» → **ALL PRIVILEGES**.

Запишите имя базы, имя пользователя и пароль — они понадобятся в `.env`.

## 2. Где будут лежать файлы — два варианта

Главное правило безопасности: **из интернета должна быть видна только папка `public`**. Всё остальное (`.env` с паролями, `storage`, `vendor`) должно лежать там, куда браузер попасть не может. Никогда не распаковывайте проект целиком в `public_html`.

### Вариант Б (рекомендуется): домен смотрит прямо в `public`

Подходит, когда cPanel позволяет выбрать папку сайта — это всегда так для **поддоменов и дополнительных доменов**.

1. cPanel → **Domains** → **Create A New Domain**.
2. Domain: `hrm.example.tj`.
3. Снять галочку «Share document root».
4. Document Root: `hrm/public`.

Проект лежит в `/home/USER/hrm`, сайт открывает `/home/USER/hrm/public`. Ничего в файлах менять не нужно.

```
/home/USER/
└── hrm/                  ← весь проект
    ├── app/ config/ vendor/ storage/ …
    ├── .env
    └── public/           ← сюда смотрит домен
```

### Вариант А: сайт должен быть в `public_html`

Когда система ставится на **основной домен**, его папку (`public_html`) в cPanel поменять нельзя. Тогда проект кладётся рядом, а в `public_html` — только содержимое папки `public`.

```
/home/USER/
├── hrm/                  ← весь проект, КРОМЕ содержимого public
│   ├── app/ config/ vendor/ storage/ …
│   └── .env
└── public_html/          ← содержимое папки public
    ├── index.php         ← с исправленными путями
    ├── .htaccess
    ├── build/
    ├── favicon.ico …
    └── storage/          ← фото (см. раздел 7)
```

После распаковки проекта в `/home/USER/hrm`:

1. Перенести **всё содержимое** `/home/USER/hrm/public/` в `/home/USER/public_html/` (включая скрытый файл `.htaccess` — в File Manager включите Settings → «Show Hidden Files»).
2. Открыть `/home/USER/public_html/index.php` и заменить его содержимое на:

```php
<?php

use Illuminate\Http\Request;

define('LARAVEL_START', microtime(true));

// Проект лежит в соседней папке hrm, а не уровнем выше.
if (file_exists($maintenance = __DIR__.'/../hrm/storage/framework/maintenance.php')) {
    require $maintenance;
}

require __DIR__.'/../hrm/vendor/autoload.php';

$app = require_once __DIR__.'/../hrm/bootstrap/app.php';

// Папка сайта — эта, а не hrm/public: здесь лежат build/ и фото.
$app->usePublicPath(__DIR__);

$app->handleRequest(Request::capture());
```

3. В `.env` обязательно указать `PUBLIC_DISK_ROOT` (раздел 7) — в этом варианте команда `storage:link` не подходит.

> При обновлениях в варианте А файл `public_html/index.php` **не перезаписывайте**, а папку `public_html/build` заменяйте новой.

## 3. Подготовка сборки на своём компьютере

На хостинге нет Node.js, поэтому фронтенд собирается локально. Библиотеки PHP (`vendor`) тоже удобнее собрать локально — тогда на сервере не нужен ни Composer, ни SSH.

Команды — для **PowerShell**, из папки проекта (`C:\laragon\www\hrm`).

### 3.1. Остановить режим разработки

Остановите `composer run dev` (Ctrl+C). Пока он работает, в папке `public` лежит файл `hot` — с ним сайт на сервере будет искать ваш компьютер вместо собранных файлов. Проверьте:

```powershell
Test-Path public\hot      # должно быть False
```

Если `True` — удалите файл: `Remove-Item public\hot`.

### 3.2. Собрать фронтенд

```powershell
npm ci
npm run build
```

Появится папка `public\build`.

### 3.3. Собрать чистую копию проекта

`git archive` берёт только то, что закоммичено, и пропускает всё лишнее: `node_modules`, `.env`, `public/hot`, тесты, служебные файлы. Поэтому случайно отправить на сервер пароль или мусор невозможно.

```powershell
# Чистая копия исходников в папку release
Remove-Item release, release-src.zip, hrm-release.zip -Recurse -Force -ErrorAction SilentlyContinue
git archive --format=zip --output=release-src.zip HEAD
Expand-Archive release-src.zip -DestinationPath release
Remove-Item release-src.zip

# Собранный фронтенд
Copy-Item public\build release\public\build -Recurse

# Библиотеки PHP — без инструментов разработки
cd release
composer install --no-dev --optimize-autoloader --no-interaction
cd ..

# Архив для загрузки на сервер
tar.exe -a -c -f hrm-release.zip -C release .
```

Получится файл `hrm-release.zip` — его и загружаем. Папка `release` и архив в git не попадают.

> **Если на сервере есть SSH и Composer**, папку `vendor` можно не собирать локально: пропустите строки с `composer install`, а на сервере после распаковки выполните
> `PHP /usr/local/bin/composer install --no-dev --optimize-autoloader` (путь к composer покажет `which composer`).

### Что НИКОГДА не должно попасть на сервер

| Что | Почему |
| --- | --- |
| `.env` с вашего компьютера | в нём настройки разработки и `APP_DEBUG=true` |
| `public/hot` | сайт будет загружать скрипты с вашего компьютера — пустая страница |
| `node_modules` | сотни мегабайт, на сервере не нужны |
| `tests`, `.git`, `.github`, `.devcontainer` | не нужны для работы |
| `vendor`, собранный **с** инструментами разработки | лишние пакеты, включая панель отладки |
| `bootstrap/cache/*.php` из рабочей папки разработки | в них записаны пакеты разработки — будет ошибка 500 |
| `storage/logs`, `storage/app` с вашего компьютера | демо-данные и чужие фото |

Если собирать архив шагами из 3.3 — всё это исключается автоматически.

## 4. Загрузка на сервер

1. cPanel → **File Manager** → перейти в `/home/USER` → создать папку `hrm`.
2. Зайти в `hrm` → **Upload** → загрузить `hrm-release.zip`.
3. Правой кнопкой по архиву → **Extract** → в `/home/USER/hrm`.
4. Удалить `hrm-release.zip` с сервера.
5. Для **варианта А** — перенести содержимое `hrm/public` в `public_html` и поправить `index.php` (раздел 2).

### Файл `.env`

1. В `/home/USER/hrm` скопировать `.env.production.example` → `.env`.
2. Открыть `.env` (правой кнопкой → Edit) и заполнить всё, что помечено `CHANGE`:
   - `APP_URL` — адрес с `https://`, без `/` в конце;
   - `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` — из раздела 1.3;
   - `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM_ADDRESS` — данные почтового ящика (cPanel → Email Accounts → Connect Devices). `MAIL_FROM_ADDRESS` должен совпадать с `MAIL_USERNAME`.
3. Убедиться: `APP_ENV=production`, `APP_DEBUG=false`.
4. Права на файл: правой кнопкой → Permissions → `600`.

Значение с пробелом или знаком `#` берите в двойные кавычки: `DB_PASSWORD="пар#оль"`.

### Права на папки

Обычно ничего менять не нужно: папки `755`, файлы `644`. PHP должен иметь право записи в:

- `storage` (и всё внутри),
- `bootstrap/cache`.

Если сайт пишет «Permission denied» — выставьте этим двум папкам `755` рекурсивно (или `775`, если так требует хостинг). **Никогда не ставьте `777`.**

## 5. Первая настройка

Дальше нужно выполнить несколько команд `artisan`. Есть два пути.

### 5.1. Есть SSH или «Terminal» в cPanel

```bash
cd /home/USER/hrm

# 1. Ключ шифрования — один раз и навсегда
PHP artisan key:generate

# 2. Таблицы в базе
PHP artisan migrate --force

# 3. Права доступа и системный администратор. Команда сама спросит его
#    фамилию, имя, пол, e-mail и пароль. Больше ничего не создаётся.
PHP artisan db:seed --class=ProductionSeeder --force

# 4. Только если на шаге 3 вопросов не было (команда так и скажет):
PHP artisan hrm:sysadmin

# 5. Ссылка на папку с фото (вариант Б). Если ошибка — см. раздел 7
PHP artisan storage:link

# 6. Ускорение: кэш настроек, маршрутов и шаблонов
PHP artisan config:cache
PHP artisan route:cache
PHP artisan view:cache
```

Проверка, что всё на месте:

```bash
PHP artisan about
```

Должно быть: `Environment: production`, `Debug Mode: OFF`, `Config/Routes/Views: CACHED`.

### 5.2. Нет ни SSH, ни Terminal

Команды можно выполнить через cron — как разовое задание.

**Шаг 1. Ключ.** На своём компьютере, в папке проекта:

```powershell
php artisan key:generate --show
```

Команда только **покажет** ключ (вида `base64:…`) и ничего не изменит. Вставьте его в `.env` на сервере: `APP_KEY=base64:…`.

**Шаг 2. Разовое задание.** cPanel → **Cron Jobs** → Common Settings: «Once Per Minute». Команда — одной строкой (подставьте свои данные администратора):

```bash
cd /home/USER/hrm && PHP artisan migrate --force >> storage/logs/install.log 2>&1 && PHP artisan db:seed --class=ProductionSeeder --force >> storage/logs/install.log 2>&1 && PHP artisan hrm:sysadmin --surname="Фамилия" --name="Имя" --sex=male --email="admin@example.tj" --password="ВременныйПароль123" --no-interaction >> storage/logs/install.log 2>&1 ; PHP artisan config:cache >> storage/logs/install.log 2>&1 ; PHP artisan route:cache >> storage/logs/install.log 2>&1 ; PHP artisan view:cache >> storage/logs/install.log 2>&1
```

`--sex` — `male` или `female`. Есть и `--patronymic="Отчество"`. Если cPanel портит русские буквы в команде — впишите фамилию и имя латиницей и исправьте их потом в своей карточке.

**Шаг 3.** Подождать 1–2 минуты, открыть в File Manager `hrm/storage/logs/install.log` и найти в нём строку «Системный администратор создан». Задание успевает запуститься несколько раз, поэтому ниже будут строки «Системный администратор уже есть…» — это нормально: первый запуск его создал, следующие отказались создавать второго.

**Шаг 4. Сразу удалить это задание из cron** — в нём записан пароль. Повторный запуск ничего не сломает (все команды безопасны при повторе, второго администратора система не создаст), но пароль в списке заданий оставлять нельзя.

**Шаг 5.** Войти в систему и сменить пароль: **Настройки → Пароль**. Удалить `install.log`.

Фото в этом случае настраиваются через `PUBLIC_DISK_ROOT` (раздел 7).

### Что создаёт `ProductionSeeder`

- все **права доступа** (список задан в коде);
- позицию **«Системный администратор»**;
- самого **системного администратора** — если его ещё нет и команду запустили в терминале, она спросит его данные. Без терминала (cron) она ничего не спрашивает и подсказывает команду `hrm:sysadmin`.

Больше **ничего**: ни позиций, ни отделов, ни должностей, ни языков, ни категорий оборудования, ни демо-сотрудников, ни демо-техники. Все справочники начинаются пустыми и заполняются в разделе **«Справочники»**. Начать стоит с позиций: доступы раздаются через них, и у сотрудника без позиции никаких доступов нет. Повторный запуск ничего из заведённого вами не трогает.

### Про системного администратора

- Он в системе **один**. Повторный запуск `hrm:sysadmin` откажет и назовёт существующего.
- Забытый пароль восстанавливается на странице входа — «Забыли пароль?» (нужна работающая почта).
- Все остальные сотрудники добавляются уже в самой системе: **Сотрудники → Добавить**. Пароль им приходит письмом.

## 6. Cron: письма и ежедневные задачи

На обычном хостинге нельзя держать постоянно работающий процесс, поэтому письма (пароль новому сотруднику, сброс пароля, подтверждение e-mail) отправляет cron: раз в минуту запускается планировщик и разбирает очередь.

cPanel → **Cron Jobs** → «Once Per Minute (\* \* \* \* \*)»:

```bash
PHP /home/USER/hrm/artisan schedule:run >/dev/null 2>&1
```

Пример с настоящим путём:

```bash
* * * * * /opt/cpanel/ea-php84/root/usr/bin/php /home/USER/hrm/artisan schedule:run >/dev/null 2>&1
```

Это **единственная** строка cron, которая нужна системе. Она:

| Что | Когда |
| --- | --- |
| отправляет письма из очереди | каждую минуту |
| удаляет неотправленные письма старше 30 дней | раз в сутки, 03:00 |
| удаляет просроченные ссылки сброса пароля | раз в сутки, 04:00 |
| ежедневные напоминания (инвентаризация и т. п.) | раз в сутки |

Время — душанбинское (`APP_TIMEZONE`), а не серверное.

Если хостинг разрешает cron только раз в 5 или 15 минут — поставьте самый частый доступный интервал. Всё будет работать, письма будут уходить с этой задержкой.

Посмотреть расписание: `PHP artisan schedule:list`.

## 7. Фото: `storage:link` и запасной вариант

Фото сотрудников и оборудования хранятся в `storage/app/public`, а браузеру отдаются по адресу `/storage/...`. Для этого в папке сайта нужна «ссылка» (symlink) на папку с фото.

**Вариант Б, ссылки разрешены** — достаточно команды:

```bash
PHP artisan storage:link
```

**Ссылки запрещены** (команда выдаёт ошибку `symlink() has been disabled` или фото не открываются), **нет терминала**, либо **вариант А** — используйте запасной способ: фото пишутся прямо в папку сайта.

1. В `.env` добавить строку (без `/` в конце):

   ```
   # вариант А
   PUBLIC_DISK_ROOT=/home/USER/public_html/storage

   # вариант Б без symlink
   PUBLIC_DISK_ROOT=/home/USER/hrm/public/storage
   ```

2. Создать эту папку `storage` в File Manager (права `755`).
3. Если в ней остался неработающий файл-ссылка `storage` — удалить его перед созданием папки.
4. Обновить кэш настроек: `PHP artisan config:cache` (без терминала — удалить файл `hrm/bootstrap/cache/config.php`).

Проверка: загрузить фото сотруднику — оно должно появиться на карточке.

> При запасном способе фото лежат **в папке сайта**, а не в `hrm/storage/app/public`. Учтите это в резервных копиях (раздел 10) и не удаляйте эту папку при обновлениях.

## 8. Проверка после установки

1. Открыть `https://hrm.example.tj` — должна появиться страница входа, в адресной строке замок.
2. Открыть `http://hrm.example.tj` (без `s`) — должно перебросить на https. Если нет: cPanel → **Domains** → включить «Force HTTPS Redirect».
3. Войти системным администратором.
4. Открыть `https://hrm.example.tj/up` — зелёная страница «Application up».
5. Открыть несуществующий адрес, например `/abc` — должна быть аккуратная страница «Страница не найдена» на русском.
6. Загрузить фото в свою карточку.

### Проверка почты и очереди

1. Выйти из системы → «Забыли пароль?» → ввести e-mail администратора.
2. В течение 1–2 минут должно прийти письмо. Проверьте и папку «Спам».

Если письмо не пришло:

```bash
PHP artisan queue:failed        # письма, которые не удалось отправить, и причина
PHP artisan queue:retry all     # отправить их ещё раз (после исправления настроек)
PHP artisan queue:flush         # удалить все неотправленные
```

Без терминала то же самое видно в **phpMyAdmin**:

- таблица `jobs` — письма, ожидающие отправки. Если строки там лежат дольше пары минут — **не работает cron** (раздел 6);
- таблица `failed_jobs` — неотправленные письма; в столбце `exception` — причина (чаще всего неверный пароль или порт почты).

Подробности ошибок — в файле `hrm/storage/logs/laravel-ГГГГ-ММ-ДД.log`.

## 9. Обновление системы

> **Важно для разработки.** До первой установки изменения схемы базы вносились прямо в исходные миграции. **С момента запуска в работу так делать нельзя**: на живой базе уже выполненная миграция повторно не запускается. Любое изменение таблиц теперь — **новая** миграция. Команды, стирающие базу (`migrate:fresh`, `migrate:reset`, `db:wipe`), на сервере заблокированы.

### Порядок

1. **Резервная копия** базы и фото (раздел 10).
2. На своём компьютере собрать новый `hrm-release.zip` (раздел 3).
3. Закрыть систему на обслуживание:

   ```bash
   cd /home/USER/hrm
   PHP artisan down --render="maintenance" --retry=60
   ```

   Сотрудники увидят страницу «Идёт обновление системы».

   `--render="maintenance"` обязателен. С ним страница рисуется **сейчас** и целиком сохраняется в `hrm/storage/framework/down`; дальше её отдаёт `index.php`, ещё не запуская систему. Без этого флага страницу рисует сама система — а на шаге 4 вы удаляете то, из чего она рисуется, и сотрудник увидит несколько минут пустое «Service Unavailable».

   Поэтому **порядок важен**: сначала этот шаг, потом удаление папок. И в варианте А страница работает за счёт строки про `maintenance.php` в `public_html/index.php` (раздел 2) — её не удалять.

4. В File Manager **удалить старый код** — папки:
   `app`, `bootstrap`, `config`, `database`, `lang`, `resources`, `routes`, `vendor`, `public/build`
   (в варианте А — `public_html/build` вместо `public/build`).

   **Не трогать:** `.env`, `storage`, `public/storage`, а в варианте А — `public_html/index.php`, `public_html/.htaccess`, `public_html/storage`.

5. Загрузить и распаковать новый `hrm-release.zip` в `/home/USER/hrm` (поверх). В варианте А — перенести новую `hrm/public/build` в `public_html/build`.
6. Применить изменения:

   ```bash
   PHP artisan migrate --force
   PHP artisan db:seed --class=ProductionSeeder --force
   PHP artisan config:cache
   PHP artisan route:cache
   PHP artisan view:cache
   PHP artisan up
   ```

   `ProductionSeeder` при обновлении нужен, чтобы в базе появились **новые права доступа**, добавленные в коде. Ваши справочники и настройки позиций он не трогает, а про администратора не спрашивает — он уже есть.

7. Проверить: войти, открыть пару страниц, посмотреть `PHP artisan queue:failed`.

### Обновление без терминала

Шаги 4–5 те же, а вместо команд — разовые задания cron (как в разделе 5.2). Их два, потому что между ними вы работаете руками в File Manager; **каждое после себя удалять**.

**Задание 1 — закрыть систему** (вместо шага 3). cPanel → Cron Jobs → «Once Per Minute»:

```bash
cd /home/USER/hrm && PHP artisan down --render="maintenance" --retry=60
```

Подождать минуту, открыть сайт и убедиться, что показана страница «Идёт обновление системы», **удалить задание** — и только потом делать шаги 4–5.

**Задание 2 — обновить и открыть** (вместо шага 6):

```bash
cd /home/USER/hrm && PHP artisan migrate --force > storage/logs/update.log 2>&1 ; PHP artisan db:seed --class=ProductionSeeder --force >> storage/logs/update.log 2>&1 ; PHP artisan config:cache >> storage/logs/update.log 2>&1 ; PHP artisan route:cache >> storage/logs/update.log 2>&1 ; PHP artisan view:cache >> storage/logs/update.log 2>&1 ; PHP artisan up >> storage/logs/update.log 2>&1
```

Задание запускается каждую минуту, поэтому после первого раза система уже открыта — проверьте `update.log` и удалите задание. Если открывать систему страшно до проверки, уберите из строки последнее `PHP artisan up` и откройте её отдельным третьим заданием.

Обновлять всё равно лучше в нерабочее время: между заданиями сайт закрыт столько, сколько занимают шаги 4–5.

### Изменили `.env`

После любого изменения `.env`:

```bash
PHP artisan config:cache
```

Без терминала — удалить файл `hrm/bootstrap/cache/config.php` (система начнёт читать `.env` напрямую; чуть медленнее, но работает).

## 10. Резервные копии

Копировать нужно три вещи:

| Что | Где | Как |
| --- | --- | --- |
| **База данных** | MySQL | cPanel → phpMyAdmin → база → **Export** → Quick → SQL. Или cPanel → Backup → «Download a MySQL Database Backup» |
| **Фото** | `hrm/storage/app` (или папка из `PUBLIC_DISK_ROOT`) | File Manager → выделить папку → **Compress** → скачать архив |
| **`.env`** | `hrm/.env` | скачать и хранить в надёжном месте, **не** в почте и не в мессенджере |

С SSH базу удобнее выгружать командой:

```bash
mysqldump -u USER_hrm -p USER_hrm > ~/hrm-$(date +%F).sql
```

**Когда:** перед каждым обновлением и регулярно — не реже раза в неделю. Копии храните **не на том же хостинге**.

**Почему важен `.env`:** в нём `APP_KEY`. Без этого ключа восстановленная система потеряет все активные входы и не сможет прочитать письма, ждавшие отправки. Данные сотрудников при этом не пострадают, но ключ лучше сохранить.

### Восстановление

1. Развернуть код (разделы 3–4), вернуть сохранённый `.env`.
2. phpMyAdmin → пустая база → **Import** → файл `.sql`.
3. Вернуть папку с фото на место.
4. `PHP artisan migrate --force`, затем `config:cache`, `route:cache`, `view:cache`.

## 11. Если что-то не работает

Первым делом смотрите журнал: `hrm/storage/logs/laravel-ГГГГ-ММ-ДД.log` (последние строки). Если этого файла нет — смотрите `error_log` в папке сайта и cPanel → **Errors**.

> Не включайте `APP_DEBUG=true` на рабочем сервере «чтобы посмотреть ошибку»: страница ошибки покажет пароли из `.env` любому посетителю. Ошибка и так записана в журнал.

### Ошибка 500 сразу после загрузки

| Причина | Что сделать |
| --- | --- |
| Версия PHP ниже 8.4 | MultiPHP Manager → 8.4 для этого домена |
| Нет `.env` или пустой `APP_KEY` | раздел 4 и шаг «Ключ» в разделе 5 |
| Нет прав на запись | `storage` и `bootstrap/cache` — `755` рекурсивно |
| Загружены `bootstrap/cache/*.php` с компьютера разработчика (в журнале: `Class "Barryvdh\Debugbar\..." not found`) | удалить **все `.php`-файлы** в `hrm/bootstrap/cache` (файл `.gitignore` оставить) |
| Неверные пути в `public_html/index.php` (вариант А) | сверить с разделом 2 |
| Не хватает расширения PHP | в журнале будет его имя; включить в Select PHP Version |
| Неверные данные базы (`Access denied for user`) | проверить `DB_*` в `.env`; имя базы и пользователя — с префиксом `USER_` |
| В журнале `Vite manifest not found` | не загружена папка `public/build` — пересобрать (раздел 3) и загрузить. В варианте А она должна быть в `public_html/build`, и в `index.php` должна быть строка `usePublicPath` |

### Пустая белая страница

| Причина | Что сделать |
| --- | --- |
| На сервер попал файл `public/hot` | удалить его |
| Адрес открыт по `http`, а `APP_URL` — `https` (или наоборот) | открыть консоль браузера (F12): если там «Mixed Content» — исправить `APP_URL`, включить «Force HTTPS Redirect», выполнить `config:cache` |
| Старая сборка в кэше браузера | Ctrl+F5 |

### Не загружаются стили и скрипты (404 на `/build/...`)

- Папка `build` не загружена или лежит не там: должна быть в папке сайта (`hrm/public/build` или `public_html/build`).
- Папка `build` — от другой версии кода. Фронтенд и код должны быть из одной сборки: пересоберите архив целиком.
- В папке сайта нет файла `.htaccess` (скрытый файл не скопировался).

### Не открываются фото (404 на `/storage/...`)

- Не выполнен `storage:link` или ссылки запрещены → раздел 7, `PUBLIC_DISK_ROOT`.
- `APP_URL` в `.env` не совпадает с настоящим адресом — адреса фото строятся из него. Исправить и выполнить `config:cache`.

### Не приходят письма

1. Есть ли строка cron (раздел 6)? Правильный ли в ней путь к PHP 8.4? Проверка: в phpMyAdmin таблица `jobs` должна пустеть за минуту.
2. `PHP artisan queue:failed` (или таблица `failed_jobs`) — там причина:
   - `Failed to authenticate` — неверный `MAIL_USERNAME` / `MAIL_PASSWORD`;
   - `Connection could not be established` — неверный `MAIL_HOST` или `MAIL_PORT` (попробуйте 465, затем 587);
   - `Sender address rejected` — `MAIL_FROM_ADDRESS` не совпадает с ящиком из `MAIL_USERNAME`.
3. После исправления `.env`: `PHP artisan config:cache`, затем `PHP artisan queue:retry all`.
4. Письмо ушло, но не дошло — проверьте «Спам». Чтобы письма не попадали в спам, в cPanel → **Email Deliverability** должны быть настроены SPF и DKIM для домена.
5. Если хостинг запрещает функцию `proc_open` — это не мешает: планировщик системы её не использует.

### Ошибка 419 / «Сессия истекла» при входе

| Причина | Что сделать |
| --- | --- |
| Сайт открыт по `http`, а в `.env` `SESSION_SECURE_COOKIE=true` | открывать по `https`; включить «Force HTTPS Redirect» |
| Нет SSL-сертификата | cPanel → SSL/TLS Status → Run AutoSSL |
| `SESSION_DOMAIN` указан неверно | оставить `SESSION_DOMAIN=null` |
| После смены `.env` не обновлён кэш | `PHP artisan config:cache` |
| Сменили `APP_KEY` | все входы сброшены — просто войти заново; ключ больше не менять |
| Страница входа долго стояла открытой | обновить страницу и войти — это нормальное поведение |

### Ссылка подтверждения нового e-mail выдаёт 403

Система считает, что открыта по `http`. Проверьте, что `APP_URL` начинается с `https://`, выполните `config:cache`. Если не помогло — сообщите разработчику: хостинг не передаёт заголовок `X-Forwarded-Proto`.

### Система осталась в режиме обслуживания

```bash
PHP artisan up
```

Без терминала — удалить файл `hrm/storage/framework/down`. Этого достаточно: лежащий рядом `maintenance.php` без него ничего не делает.

### Вместо «Идёт обновление системы» — пустое «Service Unavailable»

| Причина | Что сделать |
| --- | --- |
| Закрывали без `--render="maintenance"` | открыть систему (`PHP artisan up`) и закрыть заново командой из раздела 9 |
| Папки удалили **до** того, как закрыли систему | загрузить новый код (шаг 5) — страница появится вместе с ним |
| В `.env` изменён `APP_MAINTENANCE_DRIVER` | вернуть `APP_MAINTENANCE_DRIVER=file`: заранее нарисованную страницу отдаёт только он |
| Вариант А, из `public_html/index.php` пропала строка про `maintenance.php` | вернуть её по разделу 2 |

### Команда `migrate:fresh` пишет «This command is prohibited»

Так и задумано: на рабочем сервере команды, стирающие базу, заблокированы.

## Шпаргалка команд

```bash
cd /home/USER/hrm

PHP artisan about                 # состояние: окружение, кэш, драйверы
PHP artisan schedule:list         # что и когда запускает cron
PHP artisan queue:failed          # неотправленные письма
PHP artisan queue:retry all       # отправить их повторно
PHP artisan down --render="maintenance" --retry=60   # закрыть на обслуживание
PHP artisan up                    # открыть
PHP artisan migrate --force       # обновить таблицы
PHP artisan db:seed --class=ProductionSeeder --force   # права и системный администратор
PHP artisan hrm:sysadmin          # создать системного администратора (один раз)
PHP artisan config:cache          # после любого изменения .env
PHP artisan route:cache
PHP artisan view:cache
PHP artisan optimize:clear        # сбросить весь кэш, если что-то «залипло»
```
